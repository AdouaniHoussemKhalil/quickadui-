# Primitives

`@quickadui/primitives` is a thin adapter layer over Radix UI — the *only*
package in the monorepo that imports `radix-ui` directly. Everything above
it (including `@quickadui/core`) imports from here instead, so a future
headless-primitives-vendor swap only ever touches this one package.

Most parts here render no visual chrome of their own — no hardcoded
Tailwind classes, just a stable `data-slot` attribute for hooking your own
styles onto. The example below adds its own minimal classes by hand, which
is exactly what a consumer building directly on `primitives` (skipping
`core`) is expected to do. For QuickadUI's own default, already-styled
version of the same component, see the [Core](#core) page's `Accordion`.

<Example
  code={`<Accordion type="single" collapsible>
  <AccordionItem value="item-1" className="border-b">
    <AccordionHeader>
      <AccordionTrigger className="flex w-full items-center justify-between py-3 text-sm font-medium">
        Is it unstyled by default?
      </AccordionTrigger>
    </AccordionHeader>
    <AccordionContent className="pb-3 text-sm">
      Yes — every part here gets a data-slot, nothing else. Styling is
      @quickadui/core's job.
    </AccordionContent>
  </AccordionItem>
</Accordion>`}
>
  <Accordion type="single" collapsible className="w-full max-w-sm">
    <AccordionItem value="item-1" className="border-b border-neutral-6">
      <AccordionHeader>
        <AccordionTrigger className="flex w-full items-center justify-between py-3 text-sm font-medium">
          Is it unstyled by default?
        </AccordionTrigger>
      </AccordionHeader>
      <AccordionContent className="pb-3 text-sm text-neutral-11">
        Yes — every part here gets a <code>data-slot</code>, nothing else.
        Styling is <code>@quickadui/core</code>'s job.
      </AccordionContent>
    </AccordionItem>
  </Accordion>
</Example>

A handful of parts *are* always-styled chrome rather than unstyled
building blocks — `Tabs`, for instance, since its trigger is QuickadUI's
own visible tab button, not a generic thing a consumer composes their own
button into:

<Example
  code={`<Tabs defaultValue="one">
  <TabsList>
    <TabsTrigger value="one">One</TabsTrigger>
    <TabsTrigger value="two">Two</TabsTrigger>
  </TabsList>
  <TabsContent value="one">First panel.</TabsContent>
  <TabsContent value="two">Second panel.</TabsContent>
</Tabs>`}
>
  <Tabs defaultValue="one">
    <TabsList>
      <TabsTrigger value="one">One</TabsTrigger>
      <TabsTrigger value="two">Two</TabsTrigger>
    </TabsList>
    <TabsContent value="one">First panel.</TabsContent>
    <TabsContent value="two">Second panel.</TabsContent>
  </Tabs>
</Example>
